# Using Iṣẹ́ Studio with AI assistants

Iṣẹ́ Studio is built for AI from the ground up: everything the interface can do is an operation on the engine, with its parameters described in the code. Any assistant can drive it precisely, through commands rather than clicks, and every change it makes is one undoable revision you watch happen live.

| Assistant | How it connects | Set up |
|---|---|---|
| **Iṣẹ́ AI** (in the app) | built in: the AI panel | install Claude Code |
| **Claude in Chrome** | `window.ise` on the app's page | paste one prompt (below) |
| **Claude Desktop** | MCP server + skill | add the server and the skill |
| **Claude Code** | skill (automatic in this repo) + MCP server | one command |
| **Codex** | `AGENTS.md` (automatic) + MCP server | add the server |
| Cursor, others | MCP server | add the server |

What every route shares is generated from the code, so it is never out of date: the [skill](../skills/ise-studio/SKILL.md) (every operation with its parameters, the command line, the HTTP API, and the modelling guide), regenerated by `node tools/gen-agent-docs.mjs`.

## Iṣẹ́ AI, the built-in assistant

The AI panel (bottom right, or the sparkle in the tool rail) talks to **Claude Code running on your computer**. Install Claude Code and sign in; the engine finds it on start (or set `ISE_CLAUDE` to its path; `ISE_AI_MODEL` picks the model). Attach photos, drawings or datasheets to a message and ask in plain words: *"a wall bracket for a 40 mm pipe, 3 mm steel"*, *"route the USB pair"*, *"make the grip 5 mm longer"*.

## Claude in Chrome (the browser extension)

The app's page gives assistants a JavaScript object, **`window.ise`**: the same commands the console and Iṣẹ́ AI use. Reload the Iṣẹ́ Studio tab, then tell Claude in Chrome once:

```
This tab is Iṣẹ́ Studio, an engineering CAD app. Don't click the interface to make changes.
The page has a JavaScript object `window.ise` for assistants. Use your JavaScript tool:
1. Run `ise.help()` to see the commands.
2. Run `ise.docs()` for the guide, and `ise.docs("<topic>")` for a topic (e.g. "sketches", "components", "pcb").
3. Before using an operation, run `ise.ops("<name>")` to see its exact parameters.
4. Make changes with `ise.commit(operation, parameters)` or `ise.run([...steps])`, check them with `ise.check()`,
   and show results with `ise.view("isolate", "<part name>")`.
The full guide is also readable at http://127.0.0.1:7420/agent/
```

Save it as a Claude in Chrome shortcut (type `/` in its message box), e.g. `/ise`, and start each session with `/ise <what you want>`.

| `ise.` | Does |
|---|---|
| `help()` | the commands, in short |
| `docs(topic?)` | the guide: the overview, or a topic's page |
| `ops(filter?)` | operations and their parameters' JSON schemas |
| `tree()` · `get(name)` · `find(name)` · `entities` | what the project holds |
| `commit(op, params)` · `run(steps)` | change the design (one undo step each) |
| `check()` | every requirement and geometry check |
| `view(action, what?, value?)` | show something: `select`, `isolate`, `frame`, `hide`, `show_all`, `camera`, `explode`, `section`… |
| `undo()` · `redo()` | your own last change |

For safety, Claude in Chrome treats web pages as information, not instructions: the page cannot make it do anything, but it reads the guide when you ask it to. That is why the one-time prompt is needed.

## Claude Desktop, Claude Code, Codex, Cursor: the MCP server

`tools/ise-mcp.mjs` is an [MCP](https://modelcontextprotocol.io) server (stdio). With the engine running, its tools are:

| Tool | Does |
|---|---|
| `ise_commit` | run one operation on a project |
| `ise_operations` | the operations and their parameters, live from the running engine |
| `ise_cli` | any `ise` command (its description lists them all, from the code) |
| `ise_render` | a photoreal picture of the model, returned as an image |
| `ise_docs` | the guide, by topic (the pages are also MCP resources) |

**Claude Code**

```sh
claude mcp add ise-studio -- node /path/to/ise-studio/tools/ise-mcp.mjs
```

Inside this repository Claude Code also loads the skill by itself (`.claude/skills/ise-studio`).

**Claude Desktop**: Settings → Developer → Edit config, then under `mcpServers`:

```json
"ise-studio": { "command": "node", "args": ["/path/to/ise-studio/tools/ise-mcp.mjs"] }
```

For the skill: zip the `skills/ise-studio` folder and add it under Settings → Capabilities → Skills.

**Codex**: in `~/.codex/config.toml`:

```toml
[mcp_servers.ise-studio]
command = "node"
args = ["/path/to/ise-studio/tools/ise-mcp.mjs"]
```

Codex reads [`AGENTS.md`](../AGENTS.md) in this repository by itself.

**Cursor and other MCP clients**: add a stdio server with command `node` and argument `/path/to/ise-studio/tools/ise-mcp.mjs`. Set `ISE_URL` (or pass `--url ws://host:7420/ws`) if the engine is not on this computer's default port.

## Keeping the agent docs current

The skill, `AGENTS.md` and `CLAUDE.md` are generated from the code: the engine's command registry (operations and their documented parameters, via `target/release/ise-ops`), the usage block of `tools/ise.mjs`, the engine's HTTP routes with their handlers' doc comments, and the manual `tools/ise-ai.md`. After changing any of those:

```sh
node tools/gen-agent-docs.mjs
```

`node --test tools/agent-docs.test.mjs` fails while they are out of date. [`reference/coverage.md`](../skills/ise-studio/reference/coverage.md) lists what the code does not describe yet; every doc comment added there improves every assistant at once.
